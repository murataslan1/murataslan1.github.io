The Problem
Token Wall
Even a single microservice no longer fits into the context window.
One million tokens of input. Two hundred thousand of window. The math doesn't add up.
04
Anatomy
Where Context Bloat Comes From

Four sources.

Raw tool output

npm test, cat, grep — 50K lines dumped into context in one shot.

Session discontinuity

After compact, the model forgets everything. You re-explain — or accept wrong decisions.

Wrong division of labor

The LLM reads files and counts. That's a code job, not a language job.

Prose enforcement

Aggressive brevity prompts have been shown to degrade reasoning benchmarks.

Paradigm
Context Virtualization

Borrowed from operating systems.

Virtual memory: when RAM runs out, the OS pages to disk and pulls it back on demand.

Context-mode does the same — for LLM context.

  • RAMLLM context window
  • DiskSQLite + FTS5 sandbox
  • Faultctx_search call
  • PageOnly the relevant 50 lines

Architecture
How It Works

Three parts. One flow.

LLM MCP Sandbox ┌─────────┐ ┌──────────┐ ┌─────────────┐ │ Claude │◀──▶│ context- │◀───▶│ SQLite + │ │ Copilot │ │ mode │ │ FTS5 │ │ Gemini │ │ server │ │ (BM25) │ └─────────┘ └──────────┘ └─────────────┘ │ ▼ ┌──────────────┐ │ shell · web │ │ fs · APIs │ └──────────────┘

Command output never reaches the LLM directly. The LLM asks "what are you looking for?" and gets back only the relevant slice.

08
Solution
Context-mode Solves Four Sides

01 · Context Saving

315 KB becomes 5.4 KB. 98% reduction. Sandboxed tools keep raw data out of the window.

02 · Session Continuity

Every edit, git op, and error lands in SQLite. After compact, BM25 brings back what's relevant.

03 · Think in Code

Don't read 50 files to count — write a script and return only the result. 47×Read = 700KB → 1×ctx_execute = 3.6KB.

04 · Prose Freedom

Routes data, not voice. Brevity prompts won't quietly tank your model's reasoning.

10
Paradigm
Think in Code

The LLM is not a data processor. It's a code generator.

// Before: 47 × Read() = 700 KB of context
// After:  1 × ctx_execute() = 3.6 KB

ctx_execute("javascript", `
  const files = fs.readdirSync('src')
    .filter(f => f.endsWith('.ts'));
  files.forEach(f => console.log(
    f + ': ' + fs.readFileSync('src/'+f).split('\n').length
  ));
`);

Don't read the file — program the analysis. Put only the answer in context.
